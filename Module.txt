# Plan: Full ERP Suite — HSE real backend + HR, Finance, Operations, Payroll modules

## Context

The HSE module is fully built as a **frontend-only mockup** (all data in `types.ts` mock arrays, workflow engine in `localStorage`). The next phase is two parallel tracks:

1. **HSE → Real backend**: migrate every HSE area off mock data onto Supabase tables + Netlify/Hono API routes, following the exact same pattern as `employees.ts`, `payroll.ts`, etc.
2. **New modules**: build HR, Finance, Operations, and Payroll as full registered modules (frontend + backend), wired into the existing module registry, RBAC, and workflow engine.

All four new modules must define **integration seams** so that HSE actions (incident → finance cost, injury → HR record, permit → operations schedule) flow across them via the typed `Handoff` mechanism already in `src/lib/workflow/`.

**Scope**: Trinidad & Tobago operations, ~20–30 employees, 5 active sites. OSH Act 2004 + EMA Act compliance shapes HSE. NIS + Health Surcharge + PAYE shapes Payroll (already partially built). The `app_users` table already has payroll fields (`pay_cycle`, `pay_basis`, `hourly_rate`, `monthly_salary`, NIS/PAYE flags). `payroll_approvals` table already exists.

## Architecture Decisions

### Cross-module integration via Handoffs
Every module exposes a small **intake API** (`POST /api/<module>/intake`) that accepts a `Handoff` record from another module. HSE writes handoffs; HR/Finance/Operations consume them. The workflow engine's `emitHandoff()` call becomes a real API call when the target module exists.

Handoff types to implement:
| HSE Event | Target | Payload |
|---|---|---|
| Incident approved | HR | `{ type:'injury-record', employeeId, incidentRef, severity, lostDays }` |
| Incident approved | Finance | `{ type:'cost-claim', incidentRef, estimatedCost, costCenter }` |
| Permit approved | Operations | `{ type:'work-clearance', permitRef, site, startDate, crew[] }` |
| Environmental notification | Finance | `{ type:'ema-levy', ref, amount, dueDate }` |
| Training completion | HR | `{ type:'competency-update', employeeId, courseId, expiryDate }` |
| CAPA closed | HR | `{ type:'disciplinary-note', employeeId, capaRef }` |

### Module registration pattern (reuse exactly)
Each new module:
1. Creates `src/components/sections/<Module>/module.ts` → calls `registerModule(def)` at import
2. Adds nav items with `parent` + `defaultVisible` for nested sidebar
3. Creates `src/components/sections/<Module>/<Module>Section.tsx` → routes sectionId → page
4. Mounts via existing `mount.ts` pattern

### Permission keys (extend `src/lib/permissions.ts` + `netlify/functions/lib/permissions.ts`)
New keys per module follow the `<module>.<action>` pattern:
- HSE: `hse.incidents.view`, `hse.incidents.manage`, `hse.permits.approve`, `hse.training.certify`, etc.
- HR: `hr.employees.view`, `hr.records.manage`, `hr.disciplinary.view`
- Finance: `finance.costs.view`, `finance.costs.approve`, `finance.levies.manage`
- Operations: `operations.permits.view`, `operations.schedule.manage`
- Payroll: already partially exists (`payroll.view`, `payroll.export`, `payroll.run`)

### 1C. Frontend migration

Replace mock data with TanStack Query hooks in `src/api/hse.ts`:
```typescript
// Query hooks pattern (mirrors src/api/employees.ts)
useHseIncidents(filters)        → GET /api/hse/incidents
useHseIncident(id)              → GET /api/hse/incidents/:id
useCreateIncident()             → POST /api/hse/incidents
useHsePermits(filters)          → GET /api/hse/permits
useHseWorkflows()               → GET /api/hse/workflows
useHseApprovals()               → GET /api/hse/approvals
useDecideApproval()             → POST /api/hse/approvals/:id/decide
useHseDashboardKpis()           → GET /api/hse/dashboard/kpis
// ... one hook per resource
```

Each HSE area TSX file: swap `mockIncidents` → `useHseIncidents().data`, loading/error states, optimistic updates on mutation.

Workflow engine (`src/lib/workflow/store.ts`): add `syncToServer` flag — when true, `submitWorkflow()` calls `POST /api/hse/workflows` instead of writing localStorage. `decide()` calls `POST /api/hse/approvals/:id/decide`. `localStorage` becomes a cache layer only.
