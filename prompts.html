5 Prompts to Build a Multi-Role Attendance Dashboard

Run these in order with any capable AI assistant or hand them to a developer. Each prompt produces a working slice — after Prompt 1 you can log in, after Prompt 5 the app is fully polished.

Apps Script External Hosting Vanilla JS (no React) Bootstrap 5 DataTables 1.13.7 Chart.js + Leaflet
How to use: click Copy on a prompt, paste it into Claude / ChatGPT / Cursor, and ship the slice it returns. Run them sequentially — each prompt assumes the previous one is in place. Total build time on a fast model: roughly 6–10 hours.

Foundation — Apps Script backend, login, sidebar shell, custom popup

~ 2 hrsCode.gs + index.htmlNo prerequisites
Build the foundation of a multi-role employee attendance dashboard.

STACK
- Backend: Google Apps Script as a Web App (anonymous access). NOT bound to a Sheet — it programmatically creates one on first setup() run.
- Frontend: a single static index.html, deployable to Hostinger / Netlify / any static host. NO Apps Script template tags — plain HTML/CSS/JS.
- Vanilla JavaScript only. NO React, NO Vue, NO frameworks.
- CDNs: Bootstrap 5.3.2, Font Awesome 6.5.1, DataTables 1.13.7 + Buttons + Responsive (with bs5 styling), jQuery 3.7.1 (DataTables dep), Chart.js, Leaflet 1.9.4, jszip + pdfmake (DataTables export). NO SweetAlert2 — we will build our own popup.

BACKEND (Code.gs)

Schema — 7 sheets in one spreadsheet, created by setup():
  Users:        id, username, password, fullName, role, departmentId, position, status, createdAt, updatedAt, colorScheme, layoutMode
  Departments:  id, name, description, managerId, createdAt, updatedAt
  ProjectSites: id, name, address, latitude, longitude, radius, description, createdAt, updatedAt
  Attendance:   id, userId, username, date, checkInTime, checkOutTime, checkInLat, checkInLng, checkInAccuracy, checkInPhotoUrl, checkInSiteId, checkInDistanceM, checkOutLat, checkOutLng, checkOutAccuracy, checkOutPhotoUrl, checkOutSiteId, checkOutDistanceM, totalHours, status, notes
  LeaveRequests: id, userId, username, departmentId, type, fromDate, toDate, days, reason, status, reviewedBy, reviewedAt, reviewNotes, appliedAt
  ActivityLogs: id, timestamp, userId, username, action, entity, entityId, details
  Settings:     key, value, updatedAt

Routing:
  doPost(e) parses JSON body { action, args }. Look up action in a ROUTES map → call handler. Reads return { success: true, data:  }; writes return { success: true, ... } or { success: false, message }. Use ContentService.createTextOutput(JSON.stringify(...)).setMimeType(JSON). Frontend uses Content-Type: text/plain;charset=utf-8 to skip CORS preflight.

Auth:
  Plain-text passwords (Apps Script demo simplicity). login(username, password) returns { success, userId, username, fullName, role, departmentId, position, colorScheme, layoutMode }. logout() logs to ActivityLogs. No session tokens — frontend trust model.

setup():
  Idempotent. Creates spreadsheet if missing, ensures all 7 sheets exist with header rows, seeds Settings (companyName, lateThresholdHHMM='09:15', maxDistanceM='200', etc.) and 3 default users:
    admin / admin123       (role: admin)
    manager1 / manager123  (role: manager, dept: DEPT-001)
    employee1 / emp123     (role: employee, dept: DEPT-001)

Activity log helper log_(userId, username, action, entity, entityId, details) — used everywhere mutations succeed.

Attendance Core — selfie + GPS check-in/out, history, live map

~ 2 hrsBuilds on Prompt 1Drive scopes required
Build the attendance subsystem on top of the foundation from Prompt 1.

NEW BACKEND

markAttendance(payload) — payload: { username, action: 'CheckIn'|'CheckOut'|'Project', photoBase64, location: { latitude, longitude, accuracy } }.
  - Validate: user must be active. action must be CheckIn / CheckOut / Project.
  - haversine_(lat1, lng1, lat2, lng2): standard haversine formula, returns metres.
  - nearestSite_(lat, lng): scans ProjectSites, returns { site, distance } for closest.
  - savePhoto_(b64, username, action, dateStr): parse data URL or raw base64, save as blob to Drive folder "<Brand> Attendance Photos" (auto-create), set sharing ANYONE_WITH_LINK + VIEW, return https://lh3.google.com/u/0/d/<fileId> URL. On failure, log to ActivityLogs and return ''.
  - CheckIn: upsert today's row, write checkInTime + lat/lng/accuracy/photo/site/distance. Status = 'late' if time > settings.lateThresholdHHMM (default 09:15), else 'present'.
  - CheckOut: must have checkInTime first. Compute totalHours = round((now - checkIn) / 3600000, 2). Write checkOutTime + matching cells.
  - Use LockService (withLock_) for race-free row updates.
  - Log every action.

getMyStatus(username): returns { hasCheckedIn, hasCheckedOut, checkInTime, checkOutTime, location } for today.
getMyHistory(username, days): last N days, sorted desc by date, with selfie URLs.
getMyChart(username, year, month): { present, absent, sundays } for the given month.
getLiveAttendance(scope): rows for everyone checked in but not out today. scope='all' for admin, 'dept' for manager (filter by their dept).

Project Sites CRUD:
  listProjectSites, addProjectSite, updateProjectSite, deleteProjectSite — all admin-gated where they mutate. Each site has lat/lng/radius.

Default seed: 7 zones along a route (e.g. lat 26.68 → 26.72, lng 68.01 → 68.05) with radii 150–220m.

Live Map section (admin + manager):

SCHEMA

NEW BACKEND

updateHourlyRate({ username, rate, actorId, actorUsername }) — admin-only (verify actor.role === 'admin'). Clamp rate to ≥0. Log to ActivityLogs.

listHourlyRates() — all non-admin active employees with current rate, sorted by name. Returns [{ username, fullName, role, department, position, hourlyRate }].

bulkImportRates({ rows: [{ username, rate }, ...], actorId, actorUsername }) — admin-only. For each row, find user by username (case-insensitive), set rate. Returns { updated, skipped, total, skippedNames } so the UI can report.

getPayrollEmployees({ requesterUsername }) — admin → all active non-admins; manager → own dept only; employee → forbidden.

getPayroll({ username, year, month, requesterUsername }) — full payroll math:
  Permission check (same scope as above).
  Pull Attendance rows where userId matches and date is in [year-month-01, last-day-of-month].
  For each row: { date, checkIn, checkOut, hours: r.totalHours, status, earnings: hours × rate }.
  workingDaysInMonth_(y, mo) — count of days where weekday !== 0 (Sunday off).
  presentDays = days where status in ('present','late').
  lateDays = days where status === 'late'.
  absentDays = max(0, workingDays - presentDays).
  latePenalty = lateDays × settings.latePenaltyPerDay.
  leaveFine = absentDays × settings.leaveFinePerDay.
  grossEarnings = sum(earnings).
  netEarnings = max(0, grossEarnings - latePenalty - leaveFine).
  Return { employee:{ username, fullName, position, department, hourlyRate }, period:{ year, month, label, start, end }, days, totals:{ workingDays, presentDays, lateDays, absentDays, totalHours, grossEarnings, latePenaltyPerDay, latePenalty, leaveFinePerDay, leaveFine, netEarnings }, currency, companyName, generatedAt }.

SWR-PATTERN CACHING (vanilla, no library)

Build an `swr` IIFE module:
  swr.fetch(key, fetcher, { ttl, force, onData(data, isStale, fromCache), onError }) — returns Promise<data>.
    Behaviour: if cache has entry with age < ttl, emit cached via microtask AND return Promise.resolve(cached) without revalidation. If stale: emit cached then fetch fresh in background, emit fresh on arrival. If miss: only fetch + emit.
    In-flight dedupe — concurrent calls for the same key share one Promise.
  swr.get / set / clear / clearByPrefix(pfx) / mutate(key, data) / on(key, cb) — direct cache + subscribe API.
  swr.focusRevalidate(true) — installs a visibilitychange handler that marks subscribed keys stale on tab return.
  Default TTL: 60 000 ms.

apiSwr(action, args, opts) wrapper around fetch() to api endpoint:
  Cache key = action + ':' + JSON.stringify(args || {}).
  Hash-based render guard: maintain _swrLastHash Map; if fresh data === just-delivered cached data (by JSON hash), skip the onData callback so the table doesn't re-render and DataTables doesn't flicker.

Wrap the existing api(action, args) function: if a successful response matches the regex /^(add|update|delete|bulk|upload|approve|reject|submit|setup|login|logout)/i, call swr.clear() to invalidate everything. Reads (list*/get*) flow through apiSwr.

Capture-phase document click handler on [id^="refresh"] — clears the cache before bubble-phase loaders run, so explicit Refresh always fetches fresh.

Convert these loaders to apiSwr (skip skeleton if cached, instant render, background revalidate):
  loadEmployeeList, loadDepartments, loadProjectSites, loadAttendanceData, loadLeaveApplications, loadDepartmentEmployees, loadManagerLeaveApplications, loadHistoryInline, loadHourlyRates.

Skip on purpose (real-time): getMyStatus, getLiveAttendance, syncData, getDashboardCharts, getMyChart, login.

DATATABLES on every list view

Apply initDataTable() (built in Prompt 1) to every list table. Each loader follows the pattern:
  function loadX() {
    if (!swr.get('listX:{}')) { destroyDataTable('xTable'); setSkel(...); }
    apiSwr('listX', {}, { onData: res => displayX((res && res.success && res.data) || []) });
  }
Each display function ends with:
  initDataTable('xTable', { columnDefs: [{ targets: -1, orderable: false, searchable: false, className: 'text-center dt-no-export' }] });

destroyDataTable(tableId) — safe teardown (checks isDataTable before destroying).
